运行模式说明：系统提供三种数据源：确定性仿真推理源（12 场景预设 + 批量 A/B 实验数据，开箱即跑、结果可复现）、本机摄像头实时源（真实像素分析，见「实时监控 › 实时数据源」）、真实 YOLOv8 服务（已内置自训练权重 anquanmao.pt，启动 inference/yolov8_service.py 后执行 App.setSource()）。三者输出同一 JSON schema，前端决策链与界面无需改动。真实模型只负责「有无帽 / 佩戴规范」两路，颜色仍是真像素统计、破损仍需人工复核，边界见下方卡片。

系统架构

采集层
正面相机（人脸 / 下颚带）+ 斜上方相机（盔体 / 破损），由闸机红外信号同步取帧
身份层
人脸活体 + 1:N 比对，返回工号、工种、授权帽色
检测模型
已接入 anquanmao.pt（YOLOv8n detect，4 类：正确佩戴 / 反戴 / 未佩戴 / 佩戴非安全帽）；原方案的 head / helmet / face / strap 检测器仍作为可选分支保留
颜色分支
盔体框内 HSV 主色统计（真像素）；接入 cls_color.pt 后换成 yolov8s-cls 分类并输出颜色 → 等级映射
破损分支
规划为盔体裁剪放大至 512 后分类（完好 / 裂纹 / 凹陷 / 缺口 / 老化）；当前自训练权重无此分支，返回「未评估·需人工复核」
姿态分支
规划为 yolov8s-pose 取耳、鼻、头顶、下巴关键点 + 几何覆盖规则；当前佩戴规范由状态模型类别映射
决策层
五条规则串联，任一未通过即拒闸；支持规则开关做策略对比
执行层
开闸 / 声光报警 / 抓拍留证 / 台账记录 / 安保复核

接入真实 YOLOv8（权重已随仓库提供）

  1. 安装依赖：pip install -r inference/requirements.txt
  2. 权重已在仓库：inference/weights/anquanmao.pt；若因 zip 前缀加载失败，服务会自动生成 anquanmao_compat.pt 兼容副本
  3. 校验（可选）：python tools/verify_model.py；真实评估：python tools/evaluate.py
  4. 启动服务：python inference/yolov8_service.py --port 8000
  5. 浏览器控制台：App.setSource('http://127.0.0.1:8000')
  6. 服务 /infer 返回与本系统一致的 JSON；GET /model 与 GET /health 可查元信息与降级分支

数据与验收建议

  • 标注：目标框 / 掩码 + 颜色属性 + 破损属性 + 佩戴状态 + 人员 ID，导出 YOLO 格式与属性 JSON
  • 增强：强光、夜间补光、扬尘、反光、污渍、口罩遮挡、多人同框
  • 验收：帽检出 recall ≥ 99%，佩戴判定 ≥ 97%，颜色 ≥ 98%，破损召回 ≥ 95%，端到端 < 500 ms，误放行 = 0
  • 破损检测最难，优先保召回；小缺陷需高分辨率裁剪与真实破损样本微调
  • 断网降级：本地白名单缓存、恢复后补传；保留人工开闸与消防应急模式
  • 合规：人脸与抓拍按最小必要采集、加密存储、设置保留期与访问审计

导入外部图片检测

  • 「图片检测」标签页支持点击选择 / 拖拽上传 jpg、png、webp，或一键生成像素示例图
  • 浏览器端 Canvas 读取真实像素 → HSV 色相直方图 → 白 / 黄 / 蓝 / 红主色判定 → 12×8 网格连通聚类定位疑似安全帽区域
  • 结果复用同一套五条决策规则、中文复述、通行台账（可复述重放）与报告导出
  • 可与「场景预设」并排对比，验证同一员工在不同佩戴状态下决策链的可解释性

本机摄像头实时演示

  • 「实时监控」左侧的「实时数据源」切换为本机摄像头后，浏览器通过 getUserMedia 取流，逐帧绘制到 720 × 400 画布并实时分析
  • 颜色与疑似安全帽区域由 Canvas HSV 真实像素统计 + 12 × 8 网格聚类得出，与「图片检测」共用同一个分析函数，不是伪造的检测结果
  • 四任务输出、五条决策规则、中文复述、阈值 / 规则开关、抓拍台账与报告导出全部复用同一套引擎，切换数据源无需改动界面
  • 破损 / 佩戴方式 / 人脸活体无法由色相统计可靠推断，默认由实时复核表单填写；若已 App.setSource() 接入自训练权重，则每帧以 image_b64 送 /infer，由 anquanmao.pt 自动判定佩戴状态（破损仍需复核）
  • 隐私：视频帧只在浏览器内存中处理，不上传、不录制；离开「实时监控」页签会自动停止摄像头；仅点击「抓拍」时当前帧以内存对象存入台账，刷新页面即清除
  • 摄像头要求安全上下文（https 或 localhost）；file:// 直开可能被浏览器禁用，改用本地静态服务即可
  • 仿真模拟完全保留：切回「仿真模拟」后 12 个场景预设、阈值灵敏度扫描与批量 A/B 实验数据不受任何影响

图片模式的边界（重要）

  • 颜色与候选框是真实像素计算，不是编造的检测结果
  • 破损、佩戴方式、人脸结果无法由色相统计可靠推断，默认由操作员复核表单填写，界面与复述中均明确标注来源
  • 接入自训练权重后自动切换为模型推理：上传图片 → POST /infer（image_b64）→ anquanmao.pt 的真实检测框与 4 类佩戴状态 → 决策 / 复述；破损仍返回「未评估·需人工复核」，颜色仍为盔体框内真像素统计
  • 服务返回的是原图像素坐标，前端按标准化画布的缩放参数映射后再叠加显示
